# 循环计划 v2.8.0 · E3 能耗报告聚合 + 周报窗口修复

> 流程：编排 → 自审 → 实现 → 自检 → 发布。
> 透镜：数据完整性 + 可溯源（轮中事故优先：周报把「装上以来」说成「本周」）。

## 目标

M3-E3：日/周/月能耗聚合纯函数 + 报告/CSV/小结升级。**先修周报窗口谎言**。

## 现状

- `weeklyDigestBody` 对**全部** `dailyHistory` 求和，文案却写「本周用电」——信任事故
- `monthlyDigestBody` 已按 `yyyy-MM` 过滤，但日均用**日历天数**摊（缺记录的天被当成 0）
- `BatteryReportBuilder`【最近用电】只逐日罗列，无窗口聚合
- CSV 有每日用电表，无聚合表
- 诚实边界（计划原文）：不承诺月级电量曲线（细粒度仅 24h）

## 本轮范围

1. **修复**：`weeklyDigestBody` 强制 `due:`，只统计 due 截止近 7 日窗（与 DwellTracking 同源 dayKeys）
2. **修复**：月报日均改为「记录 N 天，日均 X%」（按有效样本日，不按日历天）
3. **新增** `EnergyAggregation` 纯函数：窗口聚合 / 峰值日 / 近窗对比 / 诚实摘要行
4. **报告**：【最近用电】前置近7日+本月聚合行（注明日均口径与无月级曲线）
5. **CSV**：新增 `# 能耗聚合` 表；`csv()` 可注入 `now` 便于测试
6. **周报文案**：有样本时带「（记录 N 天，日均 X%）」

## 自审

| # | 问 | 结论 |
|---|---|---|
| 1 | 算 bug 还是 feature？ | 周报谎言=传记失真级，作业书要求优先修；与 E3 同轮 |
| 2 | 改 API 会破坏调用方？ | `due` 必填；生产处 `checkWeeklyDigest` 已有 due；测试同步改 |
| 3 | 日均口径？ | 有效样本日（drain/charge>0 或通电≥30min）；空日不进分母 |
| 4 | 月级曲线？ | 不做；聚合行/CSV 注明诚实边界 |
| 5 | UI 骨架？ | 报告/CSV/通知文案，不改面板布局，高度门不适用 |
| 6 | 变异检验？ | 去掉周过滤必红；日均改回日历天必红；峰值写反应红 |
